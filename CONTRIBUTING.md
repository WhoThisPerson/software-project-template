# Contributing

Contributions to improve this template are welcome.

## Before Making a Change

Consider:

- What problem does the proposed change solve?
- Is the change broadly useful across different types of projects?
- Does it duplicate information already covered elsewhere?
- Does the added complexity justify the benefit?

For substantial changes, open an issue first to discuss the proposal.

## Pull Requests

When submitting a pull request:

1. Explain what was changed.
2. Explain why the change is useful.
3. Keep changes focused on a single improvement.
4. Update the README or documentation when appropriate.

## Design Philosophy

This template is intended to encourage thoughtful software design
without creating unnecessary documentation overhead.
